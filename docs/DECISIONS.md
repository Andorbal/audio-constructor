# Decision Log

Short records of choices that shape the codebase. Add a new entry rather than
silently changing a decision; mark superseded entries.

| # | Decision | Alternatives considered | Why |
| --- | --- | --- | --- |
| D1 | **Rust** for everything. | C++ with JUCE; TypeScript + a native engine. | Real-time safety without a garbage collector, first-class WebAssembly, one language for engine, CLI, app, and plugin. JUCE's wasm story and license are poor fits. |
| D2 | **egui/eframe (wgpu)** in-process UI with a custom-drawn node canvas. | Tauri + web front end; iced; Vizia; Slint. | No IPC between editor and engine telemetry; immediate mode suits live meters; same code on desktop and web and inside a plugin window (nih_plug_egui). Cost: more hand-drawn widgets; accepted. |
| D3 | **Three-rate value model** (Const / Block / Sample) inferred at compile time. | Everything audio-rate; everything control-rate with separate "~" audio nodes. | Any parameter can be modulated at audio rate without every parameter paying for it. Nodes read through accessors so they don't care. |
| D4 | **Cycles only through `Feedback`**, one block of delay. | Implicit one-sample feedback everywhere (per-sample scheduling); forbid cycles. | Keeps the scheduler a plain DAG and block-based, which is what makes it fast; feedback is explicit and visible. Single-sample feedback for cycles is a Phase 3 investigation. |
| D5 | **Determinism analysis + baking** for whole-input nodes instead of an edit/performance mode. | A global offline/realtime mode switch; forbidding non-causal nodes. | Matches the product preference: forgiving and flexible, no mode to forget, one project format, one engine. |
| D6 | **Integer sample position is the clock**; beats are derived per tempo segment. | Floating-point beat accumulator; MIDI-clock style ticks. | Exact, drift-free, reproducible. Tempo changes are segment boundaries. External sync is out of scope. |
| D7 | **JSON project files** with embedded group definitions and asset references by path + hash. | RON; binary; a project directory. | Diffable, inspectable, pasteable; embedding defs makes projects self-contained; `.acpack` zips handle sharing with assets. |
| D8 | **cpal** for audio, with **ASIO as an opt-in feature build**. | Per-platform native bindings; JUCE; PortAudio. | One API across platforms including web. The ASIO SDK can't be redistributed and binaries need a Steinberg license, so ASIO is a separate build; WASAPI exclusive covers most Windows interfaces meanwhile. |
| D9 | **CLAP first, VST3 second** for both the plugin build and plugin hosting; **no VST2**. | VST3 first; AU. | CLAP is open, well-specified, and has good Rust support (nih-plug, clack). VST3 requires Steinberg's license terms for distribution (GPLv3 or proprietary agreement). VST2 is no longer licensable. AU can follow via nih-plug if demand exists. If Rust VST3 hosting still lags when Phase 3 arrives, the fallback is a small out-of-process C++ bridge for VST3 hosting only, never a move of the engine or UI to C++/JUCE (rejected: AGPL conflicts with MIT, and no web build). |
| D10 | **One node per file, registered through a central registry**; docs generated from doc comments. | Node definitions in a data file; a scripting language for nodes. | Each node is small, reviewable, testable, and self-documenting. A scripting layer may come later as a `Script` node, not as the way built-ins are written. |
| D11 | **State carries over across recompiles** when a node's id and config are unchanged. | Reset everything on each edit. | Editing while playing is the core experience; a delay line must not go silent because a wire was added elsewhere. |
| D12 | **Polyphony is group instancing** (`Voices`), not per-node voice handling. | Polyphonic signal types carrying N voices through every node. | Any mono patch becomes polyphonic by wrapping it; nodes stay simple. Cost: voice count fixed at compile time; accepted. |
| D13 | **Implicit conversions are limited** to Float→Audio, mono upmix, Int/Bool→Float, Audio→Float. | Convert anything to anything implicitly; no implicit conversions. | The listed ones have one obvious meaning; the rest (Trigger↔Bool, Midi→Float) hide choices the user should make with a visible node. |
| D14 | **Primitive-only nodes; composites are blocks.** | Ship a Compressor node, a Reverb node, etc. | The product thesis is that users build from parts and can open any tool up. A `Compressor` block teaches more than a `Compressor` node and is just as fast. Exceptions (`Diffuser`, `PitchShift`) are made only when the primitive version is materially slower or unusable. |
| D15 | **Engine crates must compile to wasm32 from the first milestone**, enforced in CI. | Port to wasm in Phase 3. | A dependency that doesn't build for wasm is cheapest to reject on the day it's added. |
| D16 | **Headless and null-host testing is mandatory**, since CI and agent environments have no audio devices or displays. | Manual testing only. | Golden renders, determinism tests, and egui_kittest give an agent feedback it can act on without hearing or seeing anything. Manual listening tests are recorded in ROADMAP acceptance notes. |
| D17 | **Node ids are random `u64`s written as hex strings; a graph stores nodes as an ordered list** with the id inside each node. | Numeric JSON ids; a JSON object keyed by id. | Hex strings survive tools that round large JSON numbers, and hand-written projects can use short ids like `"1"`. A list keeps z-order and diffs stable. |
| D18 | **Wire endpoints are written as `"node:socket"` strings.** | `{"node": …, "socket": …}` objects; index pairs. | One line per wire keeps project files short and diffs readable; sockets stay addressed by name. |
| D19 | **Enumerated parameters (waveform, filter mode, Math op) are `Int` sockets with named choices**, stored in files by choice name. | Config entries; string-typed sockets. | "Every parameter is a socket": a shape can be wired from any `Int` source. Names in files survive reordering of the choices. |
| D20 | **Unwired generator `start` offers *On transport play* / *On load* / *Never*; `stop` offers *On transport stop* / *Never*.** | Only play/never; free-running generators. | *On load* covers instruments that should sound without pressing play (a synth patch played from a keyboard). *On load* re-fires after a transport reset so reset generators come back. |
| D21 | **Beats are quarter notes; tempo segments are stored at beat positions** and resolved to integer sample starts at the engine's rate. | Segments stored at sample positions. | Musical positions stay correct when the engine runs at the device's rate rather than the project's nominal rate. Within a segment, beat ↔ sample math is `f64` relative to the segment start and rounded once. |
| D22 | **Telemetry (meters, scopes, readouts, timings) is published through relaxed atomics** the UI reads at frame rate. | `triple_buffer` snapshots. | Meters don't need snapshot consistency, atomics are wait-free with no unsafe code or extra dependency, and the layout can be shared by `Arc` with the UI. |
| D23 | **Node I/O borrows are split safely by moving a step's output buffers out of the pool** for the duration of `process` (a pointer swap, no allocation). | Raw pointers into one arena with `unsafe`; per-sample `Cell`s. | No `unsafe` on the audio path, and the compiler's no-aliasing guarantee still lets the optimizer vectorize node loops. |
| D24 | **Mute is a bypass in the scheduler**: a muted node's step copies `in` to `out` when both are Audio or both Float/Bool, otherwise outputs silence; a muted group mutes everything inside it. | A per-node mute flag each node must honor. | One rule for every node, no node code to get wrong, and the node keeps its state for when it's unmuted. |
| D25 | **Nodes on a cycle without a Feedback node are left out of the schedule** (reported by name); inputs they fed become unwired so everything downstream still runs. | Reject the whole project; cut an arbitrary edge. | Errors never block the rest of the graph (UX principle 5), and the report says exactly which nodes to fix. |
| D26 | **Clock ticks, gates, and counts are computed from the transport position on a grid from transport zero**, never accumulated; interval changes take effect at the next tick. | A running phase accumulator. | Drift-free and reproducible, and a seek lands on the right tick (DECISIONS D6). |
| D27 | **MIDI Note falls back legato** (gate stays high, no new trigger) when the active key is released while others are held; glide is linear in semitones; at most 16 held keys (oldest dropped). | Retrigger on fallback; exponential glide. | Matches how monophonic synths are usually played, and the fixed key stack keeps the audio path allocation-free. |
| D28 | **Record starts and stops takes on block boundaries**, and records while `arm` is on *and* the transport is recording (or between its own `start`/`stop` triggers). | Sample-accurate punch in/out; record whenever armed. | `R` in the transport records every armed Record node, like a tape machine; block granularity (a few ms) is fine for takes and keeps `RecordSink` simple. Sample-accurate punch-in can come with the Phase 2 `Buffer` output. |
| D29 | **Out-of-range configs are repaired, not rejected**: channel counts clamp (Audio In/Out 1–2, Record 1–16, Feedback/Split/Merge 1–32, Mix 1–64), a Slider's reversed range is swapped, unknown units become generic. | Compile errors for bad configs. | No panics or dead nodes on hand-edited files (CLAUDE.md non-negotiable 5); the clamped value is visible in the editor. |
| D30 | **Node outputs are kept finite where a loop could amplify a bad value** (Feedback stores NaN/inf as 0; Math/Unary/Map map domain errors to 0) while probes report raw values (Readout may show NaN). | Sanitize everywhere; sanitize nowhere. | One NaN in a feedback loop would otherwise poison a patch until reset; a debugging probe should show the truth. |
| D31 | **Events landing on the same frame apply in a fixed, documented order** (Oscillator: stop, start, reset, sync; Clip: reverse, stop, start, reset; ADSR: release before attack), and generators fire `end` only if they were playing. | Wire order; unspecified. | Same-frame events are common (a Clock driving several sockets); a fixed order keeps renders deterministic and patches predictable. |
| D32 | **Time inputs that are within f32 rounding of a whole sample count snap to it** (0.01 s is exactly 480 samples at 48 kHz). | Always truncate or round. | Delay times and envelope stages typed as round numbers land on exact samples, which makes tests and golden renders exact. |
| D33 | **Clip resamples once on load with a Kaiser-windowed sinc** (32 zero crossings, β = 8, cutoff at 0.92 of the lower Nyquist); playback at other rates uses cubic Hermite interpolation. | Linear interpolation; resampling per block. | Load-time quality costs nothing at play time; Hermite is cheap and clean enough for rate changes and scrubbing. |
| D34 | **Delay lines clear in constant time** (a fill counter instead of zeroing). | `fill(0.0)` on reset. | A transport reset with a 60 s delay would otherwise write ~90 MB on the audio thread. |
| D35 | **Node state is sized from `PrepareCtx`, which doesn't yet carry input channel counts**: Biquad keeps state for up to 64 channels, Delay keeps lines for 2 and passes further channels dry. | Pass channel counts to `new()`. | Phase 1 patches are mono or stereo. Passing channel counts (and adding them to the carry-over key) is a small engine change scheduled with Phase 2's multichannel work. |
| D36 | **Duplex audio is a separate input stream feeding an SPSC ring that the output callback drains**, with a one-buffer cushion; a dry ring zero-fills and a backed-up ring skips back to the cushion, both counted as device xruns. | Platform duplex APIs; locking a shared buffer. | One path for duplex interfaces and for two separate devices, on every backend cpal supports, without locks. |
| D37 | **MIDI is stamped on one monotonic clock and placed one block late** (`offset = (t_recv − (t_callback − block)) × rate`), one ring per source (up to 16), note-off sorted before note-on at the same offset. | Quantize to the callback; one shared ring. | Removes the jitter of callback-boundary quantization for the cost of one buffer; per-source rings mean no producer waits on another. |
| D38 | **Audio backends implement `AudioHost`/`AudioStream`; there is no `MidiHost` trait** — virtual MIDI sources (computer keyboard, tests) use `MidiSender` into the same receiver. Stopping a stream hands the processor back, so devices can be switched without rebuilding the engine. | A trait per backend kind. | The traits cover what hosts actually swap (cpal vs. null); MIDI sources differ only in where bytes come from. |
| D39 | **Recording commands carry the sample position they apply at; each sink buffers 5 s; takes are claimed with `create_new`** (`<name>-NNN.wav`, 32-bit float by default). | Unbounded queues; timestamp-free commands. | Wait-free on the audio thread, never overwrites an earlier take, and a slow disk loses counted samples rather than stalling audio. |
| D40 | **Latency is measured with a pseudo-random noise burst and FFT cross-correlation** (minimum confidence 0.2), pausing the engine for about a second. | Single click; chirp. | A noise burst correlates sharply even through filtering converters; the confidence floor turns "no cable" into a clear message instead of a bogus number. |
| D41 | **Device output is made safe at the boundary**: NaN/inf become 0 and samples clamp to ±1 for every format. | Trust the graph. | A bad patch must never send garbage to speakers or ears. |
| D42 | **Real-time priority**: cpal's `realtime` feature (MMCSS on Windows) plus a SCHED_FIFO request for the ALSA callback thread on Linux, made once at stream start; refusals produce one warning. | Require root or rtkit; no priority. | Lower xrun rates where the system allows it, without a D-Bus dependency or failing where it doesn't. |
| D43 | **Editor undo snapshots the whole project per step**; parameter drags on the same socket within a second merge into one step, and steps that changed nothing are dropped. | A command/inverse-command undo system. | Correct for every operation by construction (groups, paste, config changes) at Phase 1 project sizes; revisit if projects get large enough for snapshots to cost. |
| D44 | **Inside a group, the interface is edited as two virtual cards** (group input / group output) whose wires map onto the definition's interface; dropping a wire on a card's open socket adds an interface socket. | A separate interface editor dialog. | Exposing a socket is a wiring gesture like any other, so there's no mode or dialog to learn (UX principle 1). |
| D45 | **Each group scope remembers its own view; projects without a stored view are framed to the window on open** (the shipped examples store none). | One global view; always restore stored views. | Entering and leaving groups keeps your place, and examples look right at any window size. |
| D46 | **`Space` acts on key release and not at all if the press was used to pan; `=` zooms in like `+`.** | Act on press. | Space+drag pans the canvas without toggling the transport; `+` needs Shift on most layouts. |
| D47 | **Phosphor icons are vendored as a font subset in the private-use area and placed first in the fallback chain.** | The crate's font as-is. | Inter also has glyphs in the private-use area, which showed instead of the icons. |
| D48 | **With no openable audio device, the editor runs on the paced null stream** (48 kHz, 256 frames) and says so in the status bar; devices are switched by handing the processor between streams, rebuilding the engine only when the rate changes. | Refuse to start; rebuild on every switch. | The editor always opens and stays live (meters, scopes) on machines without audio, and switching outputs keeps delay tails and envelopes. |
| D49 | **Native file dialogs via `rfd`, with an in-app path prompt as the fallback** when no portal is available (`AC_NO_NATIVE_DIALOGS=1` forces it). | Native only; in-app only. | Native dialogs where they work; never a dead button on minimal Linux desktops or in CI. |
| D50 | **Assets assigned to a Clip are copied into `<project>/assets/`, deduplicated by content hash; Save As to a new folder gathers referenced assets.** | Reference files where they are. | Projects stay self-contained and portable (ARCHITECTURE §12) without duplicate copies of the same file. |
| D51 | **Each merge request carries its own version bump and `CHANGELOG.md` section; merging to `main` releases it** once CI passes there (tag `vX.Y.Z` at the merge, binaries, the section as notes). CI rejects a merge request whose version isn't newer than `main`'s. | A bot bumps the version on merge from labels or commit messages; tagging by hand. | The version and the notes are reviewed with the change, and nothing but merges writes to `main`, so branch protection holds. Two merge requests claiming one version collide as a changelog conflict before merging instead of as a wrong release after. |
| D52 | **One version for the whole workspace**, starting at 0.1.0 for Phase 1; release archives hold the plain, unsigned binaries and the examples until signed installers arrive (M3.5). | A version per crate; no binaries before M3.5. | The crates aren't published separately, so one number names a build. Prebuilt binaries let people try a release without a Rust toolchain. |
| D53 | **`Buffer` values are shared `Arc<AudioData>` handles held per output slot (they persist across blocks); whoever creates a buffer keeps its own handle off the audio thread until no one else holds it. `Spectrum` wires carry the frames that completed in the block, each stamped with its sample offset, in storage sized at compile time from the producer's FFT size and hop** (outputs without a shape follow their first Spectrum input). | Copy buffers into the graph; one spectrum frame per block. | Cloning and dropping a handle is an atomic count, never a free, so a 10-minute take can move between nodes on the audio thread. Frame stamps keep spectral processing sample-accurate at any hop/block ratio, and nothing allocates. |
| D54 | **Whole-input nodes don't stream: they implement `render_whole`, and the engine bakes them.** A bake renders the node's upstream subgraph with fresh node instances, captures every input, calls `render_whole`, and the running graph streams the result at the transport position (silence while stopped or past the end). Bakes are keyed by a hash of everything upstream; a changed key plays the old bake until the new one arrives. Any live source upstream disables the node live; offline renders bake everything. | Nodes buffer their own input; a global offline mode. | Node authors write one pure function, and the disabling, baking, invalidation, and streaming rules (ARCHITECTURE §9) live in one place. Playing the stale bake keeps sound while a slider moves. |
| D55 | **Bakes render from transport zero over the project length (or the render's end offline), once, without looping, at the project's render block size** whatever the engine's block size. | Bake the loop region; bake at the device block size. | The same bake live and offline, so `audioc render` matches what the editor plays. A loop region replays the first pass's content, which is the simple, predictable reading. |
| D56 | **Latency compensation delays audio, sample-rate floats, triggers, and MIDI; block-rate values, ints, spectra, and buffers aren't delayed.** The delays are internal nodes under the input they feed, so they carry over across recompiles. The `Latency` node reports the *path latency* at its output, not the compensation at its input. | Compensate audio only; compensate every input. | Sample-accurate signals are the ones a misalignment smears; a slider or a bar count delayed by a few ms changes nothing audible. A single-input node is never compensated, so reporting compensation would always read 0; path latency is what debugging needs. |
| D57 | **The multi-core scheduler runs the schedule in waves** (a step's wave is one more than the latest wave it reads), moving each wave's outputs into work slots, splitting its steps into a few jobs per thread that threads claim from one lock-free counter, and running steps that write device outputs last, one at a time, on the audio thread. Buffers are reused only across waves. The audio thread works too and waits only for jobs another thread has claimed; idle workers spin, then yield, then sleep. The worker hand-off is the engine's only `unsafe` code. | Per-node task graph with dependency counters; scoped threads per block; locks. | Waves make reuse rules and determinism simple (output is bit-identical on any thread count), the barrier per wave costs microseconds, and no system call or allocation happens on the audio thread. Never waiting for a sleeping worker means a late worker costs parallelism, not an xrun. |
| D58 | **Engine threads default to one; hosts opt in to a worker pool** (`audioc run --threads`, the Devices tab). Workers ask for real-time priority where this build can grant it (Linux). | Use every core by default. | Workers busy-wait while audio plays, which costs battery and heat; small patches don't need them. Big patches and many voices are where the choice pays off, and the per-core load display shows it. |
| D59 | **Voices expands in the flattener**: an allocator node gives each copy of the body its own MIDI stream (paths `voices/<voice>/…`), `Voice` nodes inside read it, and internal summing nodes add the copies' Audio and Float outputs (other types come from the first voice). A new note takes a free voice, the one released longest ago first; busy voices are stolen by age or pitch, or the note is ignored. A retriggered voice drops its gate for one sample. | Polyphonic signal types; a voice index on every node. | Per-voice MIDI keeps the body an ordinary patch (a `MIDI Note` inside gets glide and priority for free) and lets the multi-core scheduler run voices side by side. The one-sample gate dip is what makes envelopes restart on a stolen voice. |
| D60 | **`Record`'s `buffer` comes from the host's sink**: the disk thread keeps each take in memory too (up to ten minutes) and hands it back through a ring after the file is complete. Without a recorder (quick renders), there is no buffer. | Preallocate an in-memory take in the node; read the file back. | The node never allocates or waits, and the buffer is the same audio as the file. Ten minutes bounds memory for long takes, which stay complete on disk. |
| D61 | **`File Out` writes only in offline renders, into memory the render reserves up front; the host writes the files afterwards.** Paths are relative to the main output's folder, and paths that could leave it (absolute, `..`) are refused. Live, the node does nothing (`Record` captures performances). | A disk-thread sink like `Record`'s; paths relative to the project. | Offline renders run faster than real time, so a disk ring would drop audio; memory sized from the render length never does and keeps the engine free of I/O. A shared project must not be able to write anywhere on the machine, and stems belong next to the mix. |
| D62 | **MIDI output leaves one block after the callback that produced it, timed by a sender thread; hosts send to no port until one is chosen.** `MIDI Out` runs on the device-output path, ends the notes it started when the transport stops, and has a `panic` trigger. Offline renders collect the messages (`audioc render --midi-out` writes a standard MIDI file timed by the tempo map). | Send from the audio thread at callback time; send to every port by default. | Sending is a system call, so it can't happen on the audio thread, and the one-block delay mirrors MIDI input, so spacing matches the audio. Sending everywhere by default can loop back into an input or wake hardware unexpectedly. |
| D63 | **Trigger nodes share timing rules**: triggers on one input in the same frame count once, and an output fires at most once per frame. Nodes that schedule triggers into later blocks (Trigger Delay, Clock Multiply, Burst) and Timer count their own frames, so they run with the transport stopped. Beats convert at the tempo when a trigger arrives. Timer stops itself at `duration`, so `running` is a gate of exact length. Clock Multiply passes the first trigger after a reset alone, because it has no interval yet. | Count every trigger; follow tempo changes during a wait; run the timer until `stop`. | One trigger per frame can't overflow the engine's fixed trigger buffers, and duplicates in one frame carry no information. Following tempo changes mid-wait would need re-planning every block. A self-stopping timer makes a one-shot gate without a feedback wire. |
| D64 | **Gate- and clock-driven modulators don't take the generator contract.** ADSR, Envelope, LFO, and StepSequencer restart from their own inputs (`gate`/`trigger`, `retrigger`, `reset`); an LFO in Hz runs freely, even while stopped, and in beats follows the transport position (D26). Envelope restarts jump to the first point (unlike ADSR, which starts from its current level), so curves that start high work. | Give every time-varying node start/stop/reset/loop/rate. | The contract is for things that play a timeline (clips, patterns, curves); a modulator's timeline *is* its gate or clock, and extra start/stop sockets would duplicate them and clutter every card. |
| D65 | **Routing nodes (`Select`, `Switch`) are typed by config, wrap their index, crossfade audio over 5 ms with a separate gain slew per input, and release held MIDI notes and the sustain pedal when the route changes.** Float and Bool routing follow the fastest input's rate; outputs stay finite (D30). | One node per type; clamp the index; switch hard. | One node with a type keeps the palette small. A wrapping index lets a free-running Counter cycle through inputs. Hard switching clicks, and a route change mustn't leave notes hanging. |
| D66 | **`Random` holds a position within its range, not a value**: moving `min`/`max` moves the output at once, and it starts mid-range before the first trigger. `Integrate`'s bounds are switched on by a `clamp` input (like `Map`) and never wind up past them. `Convert`'s dB → gain has no floor. Block-rate `Differentiate` divides by the previous block's length. Counters report the value after the block's events. | Hold the drawn value; clamp only the output; floor dB at −60. | Live ranges are what a performer expects from a knob on `max`; wind-up makes a clamped integrator sluggish to return; a floor in a converter would surprise people doing arithmetic. |
| D67 | **Nodes that send notes owe every note-off, and keep room for them.** Several held inputs mapping to one output note send it once and release it with the last holder (a reference count); a repeated note-on retriggers (note-off then note-on on the same sample). Past the per-block MIDI capacity (`ac_core::MIDI_CAPACITY`, shared by the engine and the test harness), nodes drop note-ons and pass-through messages, never note-offs. After `reset()`, which has no output, owed note-offs go out at frame 0 of the next block. | Pass every message through and let buffers overflow; send note-offs from `reset()`. | A hanging note is the worst failure a MIDI node can have; a dropped note-on is barely noticed. One shared constant keeps the nodes' budget and the engine's buffers in step. |
| D68 | **`MidiPattern` keeps its own clock and plays from an anchor**: a note at clip beat `p` plays at `tempo.sample_at(anchor_beat + (p − anchor_pos) / rate)`, re-anchored at start, reset, and rate changes, and loop `k` sits at `k × length` (multiplied, not accumulated). It plays with the transport stopped when started by a trigger. `Pattern` arms on `start` and plays its first step on the next clock; with loop off, the clock after the last step stops it and fires `end`, so patterns chain on the beat. Rows count from 0. | Recompute everything from the transport position; advance on start. | Anchoring follows tempo changes exactly without drift and lets the rate change mid-clip; arming on start keeps the first step on the beat of the clock that drives it. |
| D69 | **Arpeggiator note length is `gate` × the last clock interval** (one beat until two clocks have arrived); `gate` 1 is legato, with a timeout of two intervals so a stopped clock can't hang a note. **Transpose snap shifts first, then snaps to the nearest scale note** (ties go down); it isn't a transposition by scale degrees. Chord `spread` raises every second note (after inversion) by `spread` octaves. | Fixed note lengths; diatonic transposition; spread as even spacing. | Clock-relative gates follow any clock source; snap-after-shift works for any scale, including custom masks. |
| D70 | **`Lookahead` has two outputs from one input, `out` (delayed, reported as latency) and `early` (undelayed).** Latency compensation (D56) lines up parallel paths, so a detector fed from the original signal would be delayed too; a node's own outputs are never compensated against each other, so `early` keeps its head start. `early` mixed with other audio arrives early, which its help says. | A single delayed output, relying on the user to tap the input before it. | With compensation on, tapping the input gives the detector no head start at all. |
| D71 | **`Shaper` oversamples 2× (51-tap halfband), reporting 25 samples of latency and delaying its dry mix to match; a static bias offset is subtracted rather than filtered.** All curves have unit slope at zero. | Antiderivative anti-aliasing; a DC blocker after the curve. | ADAA rolls off ~12 dB at 20 kHz in the linear region; subtracting f(bias) − f(0) keeps silence silent and keeps custom curves usable as control mappings, where a DC blocker would distort slow signals. |
| D72 | **`Normalize`'s `mode` (peak or LUFS) is config, not a choice socket**, because the `target` default differs by mode (−1 dBFS, −14 LUFS) and a socket default can't depend on another socket. Sample peak, not true peak; LUFS gates per BS.1770 and measures signals quieter than −70 LUFS or shorter than 400 ms without the gates. | A choice socket with one shared default. | Same precedent as Delay's and Graph's `unit`: config is for what changes the socket list or its defaults. |
| D73 | **Generators latch their source at `start` and keep exact time by counting samples.** `Sampler` latches the sound at `start` (frames before a mid-block retrigger keep the old one) and plays other-rate buffers through a speed factor, never resampling on the audio thread. `Graph` rescales its count when `duration` changes, keeping its place. `Wavetable` builds buffer tables lazily into storage reserved up front, one FFT every 16 samples at fixed positions, so output doesn't depend on block size. `Noise` draws twice per sample whatever the color, so switching color never shifts the sequence. | Resample buffers on change; rebuild tables in `new()` only. | Real-time safety and determinism first; a buffer can arrive at runtime (Record → Sampler), so its tables can't all be built at compile time. |
| D74 | **Spectra carry their producer's path latency, though they still aren't delayed (D56)**: a node reading a spectrum and audio delays the audio to the spectrum's latency, so a dry path mixed with FFT → … → IFFT cancels to within a few LSB. FFT reports `size − 1` and stamps each frame at the sample its window ends; IFFT reports 0 (it learns the frame size only from frames, so it plans every power-of-two size up front). | Treat Spectrum wires as latency-free; give IFFT the latency. | The FFT is where the wait happens, and carrying it through the wire keeps every spectral chain lined up without the spectral nodes knowing about each other. |
| D75 | **IFFT resynthesizes by least squares (Griffin & Lim): it divides by the overlapped sum of squared windows at each position**, exact for every window at overlap 2 and up; at overlap 1, tapered windows can't reconstruct, so their weighting is floored at 10 % of the largest sum. `SpectralGate`'s threshold is absolute per bin (0 dB = a full-scale sine under Hann). FFT, PitchDetect, FrequencyTrigger, and Onset read the first channel. | Divide by the average overlap gain; a threshold relative to the frame's peak. | Average-gain OLA ripples for Blackman at 4× and Hann at 2×; an absolute threshold behaves the same on quiet and loud material. |
